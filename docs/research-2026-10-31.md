# Research workflows, 2026-10-30/31: what each found

All numbers are predictions unless marked measured. Each workflow had adversarial reviewers; refuted claims are noted.

## Code gap audit (5 readers + skeptics)
- Holds: the API splits decode users into groups of 28 (`BMAX/(MAX_DRAFTS+1)`) even with drafts off. A row packer
  predicts 32u +30%, 128u 557 -> 750-815 tok/s from the packer alone.
- Holds: dense batched kernels at 17-256 rows run at ~0.2-0.25 TB/s; an LDS-staged MX-FP8 GEMM saves ~9-10 ms at B=128.
- Refuted: "the B=8 expert kernel is limited by VALU decode" (the same per-weight work runs at ~5.4 TB/s at B=128).
  A kill test decides before any scaled-MFMA work.
- Corrected: "1.74 ms activation prep" is all 240 `prep_t` launches per step, not only expert prep.

## External sweep (web + parallel.ai)
- Persistent MoE kernels over a task map (vLLM HPC-Ops 1.59x avg on H20; Zyphra MI355X two-stage fused MoE; AITER
  fused MoE preamble M=8 65.2 -> 51.9 us).
- Batch-aware MTP: published gains fall with concurrency (AMD ROCm blog c8 1.70x ... c64 1.25x, lossy accept).
- Data-parallel replicas beat one model spread over N GPUs when the model fits on one GPU.
- Floors recalibrated to the measured read ceiling (~6.3 TB/s, not 8 TB/s).

## Structure panel (3 designs, 3 judges)
- A persistent run-ahead decode kernel scored highest on gain but lowest on feasibility: build it in parts.
- Large batch: remove the 28-user grouping first; expert-parallel over 2 GPUs adds only ~13% over two replicas.

## Byte reduction
- The stock batch sweep copies one prompt into every slot (expert union too small): real B=8 floor ~6.1 ms.
- The batched path costs 14.2 ms at B=1 vs 8.2 ms single-user: port the single-user structure (up to -5.8 ms at 8u).
- A 4-position verify at 8 users = 32 rows hits the BF16-twin threshold (+4.7 GB read): raise the threshold.
- Router + shared expert and the head should use hipBLAS at >= 64 rows (~-4-5 ms each at 128u).
- Lossy options held for approval: fewer routed experts, colder experts at lower bits.

## Determinism map
- All float atomics and split-K sums listed (file:line). Fix: "pair buffers" - each address gets at most 2 adds onto
  +0, which is order-independent in IEEE; consumers sum buffers in a fixed tree. Estimated cost < 0.5%.

## Speculative decoding lab
- The failed greedy gate was the plain arm (no drafts): A/A noise, not a speculation bug.
- Real difference: kernel family chosen from total rows, not users, so verify rows can round differently. Fix: choose
  by session count; interim: raise the BF16 threshold.
- Policy by users and prompt type (prose vs code) from measured acceptance.

## Free expert review (5 viewpoints + skeptics)
- Plain decode should skip the verify/commit path; any-order kernel dispatch with device counters; promote CB3 experts
  to MXFP4 with free HBM; async next step; Engram off the step start; cheaper draft head.
- Bugs: null-stream copy race; DSpark row assert that would kill requests once the packer lands; slot history past
  the stop token; temperature 1.0 default with GPU sampling off.

  Wrong claims corrected; 8 method rules added (heretic only, interleaved runs, md5, 2 A/A pairs, ...).
